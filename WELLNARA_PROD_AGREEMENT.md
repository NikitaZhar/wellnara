# Wellnara — путь выхода в прод

Единый источник правды по выводу Wellnara в прод. **Подчинён** `WELLNARA_WORKING_AGREEMENT.md`
(при противоречии приоритет у основного). Раздел «Готово» — журнал завершённого: что в нём
отмечено, **повторно не проверяется и не переделывается**. Двигаемся только по «Осталось».

Две части: **Приоритет 1** — минимум для запуска MVP на 20–30 клиентов, один инстанс.
**Приоритет 2** — долг по мере роста.

## Готово ✅ (не трогаем, не перепроверяем)

**База и миграции**
- `V1__baseline.sql` восстановлен. **Flyway V1→V5 многократно применялись на боевом
  PostgreSQL 17**: схема с нуля, `validate` проходит, админ создаётся. Проверка миграций закрыта.
- Postgres-специфика реально на месте: CHECK статусов (V3), уникальные индексы
  `uk_appointments_active_slot` и `uk_wallet_entries_final_per_appointment` + `@Version` (V5).
  Backstop гонки на уровне БД — есть.
- `ddl-auto=validate`; Flyway владеет схемой.

**Конфигурация**
- Профили `dev`/`prod`; секреты только из окружения; `.env` в `.gitignore`.
- `.env.example` дополнен до полного набора (15 переменных; была потеряна обязательная
  `DB_USERNAME`). `application-prod.properties` полностью env-driven.

**Безопасность**
- BCrypt; CSRF; заголовки + HSTS; ролевая авторизация; локаут логина.
- **Session fixation закрыт:** `SecuritySessionService.establish` ротирует session id при входе.

**Обработка ошибок на критичных флоу**
- **`MailException`** в обоих инвайт-контроллерах (клиент и провайдер) → дружелюбное
  сообщение вместо 500.
- **Гонка бронирования:** `requestAppointment` ловит `DataIntegrityViolationException`
  (нарушение индекса V5) → «слот занят» вместо 500. *(Перевод исключения на уровне commit
  стоит подтвердить живым тестом двойной брони при первом прогоне на проде.)*

**Качество и UI**
- Тесты (147+) зелёные на JDK 17 — включая правки выше.
- UI переоформлен (Sea Glass); `error.html` + `AppErrorController`.

## Приоритет 1 — MVP выход в прод (осталось только хостинг-зависимое)

Кодовая часть MVP закрыта (см. «Готово»). Всё оставшееся нельзя завершить до выбора платформы.

### 1. Прод-Postgres и секреты
Поднять managed/self Postgres; заполнить переменные из `.env.example` в секрет-сторе хостинга.
**Грабля:** прод-роль (`DB_USERNAME`) должна **владеть схемой `public`** (Postgres 15+, иначе
`permission denied for schema public`). SQL и runbook — в `wellnara-step1/`.

### 2. HTTPS и cookie
Терминировать TLS; в `application-prod.properties`: `server.forward-headers-strategy=framework`,
`server.servlet.session.cookie.secure=true`, `...same-site=lax`, `...session.timeout=30m`.
(Код session fixation уже сделан — см. «Готово».)

### 3. Рабочий SMTP
Настроить провайдера, SPF/DKIM для домена отправителя; проверить доставку инвайта на проде.
(Обработка `MailException` в коде уже сделана.)

### 4. Бэкапы БД
Автобэкапы managed-Postgres (или `pg_dump` по расписанию); один раз проверить восстановление.

### 5. Деплой
`./mvnw clean package`; запустить jar с профилем `prod`. Если платформа задаёт порт —
`server.port=${PORT:8080}`. Финальный смоук: инвайт → регистрация → бронь → кошелёк
(заодно подтвердить перевод исключения гонки из «Готово»).

## Приоритет 2 — долг по мере роста

По убыванию ценности; не начинать раньше нужды.

1. **Шедулер закрытия просроченных термов** — холд заморожен до ручного действия. Первый после запуска.
2. **Наблюдаемость:** actuator health/readiness + метрики + структурные логи; автоперезапуск.
3. **Глобальный `@ControllerAdvice`** для доменных ошибок (общий механизм вместо точечных catch).
4. **Вынос сессии** (Redis/JDBC) — для 2+ инстансов; до этого рестарт разлогинивает (принято).
5. **Docker + CI.**
6. **Аудитные `createdAt/updatedAt` в UTC** — §5 основного соглашения.
7. **Лазейка переноса 12–24ч** — закрыть или принять.
8. **Rate limiting и парольная политика.**
9. **Self-host шрифтов.**
