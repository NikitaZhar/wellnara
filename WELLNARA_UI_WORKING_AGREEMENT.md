# Wellnara — рабочее соглашение по UI

Этот документ фиксирует постоянные требования к работе над оформлением (frontend/UI)
приложения Wellnara. Он **подчинён** основному `WELLNARA_WORKING_AGREEMENT.md`:
при любом противоречии приоритет у основного соглашения. Действует по умолчанию
в каждой сессии по UI и не требует повторного напоминания.

Цель документа — чтобы следующая сессия продолжала оформление в том же ключе без
повторного выбора направления, повторного объяснения решений и без риска сломать бэкенд.

---

## 1. Направление оформления: Sea Glass

Выбранный дизайн-язык — **Sea Glass**: приглушённый сине-зелёный (доверие + спокойствие)
и тёплый песочный акцент (тепло, «человечность»). Это осознанный выбор из 17 проработанных
вариантов; основание — психология восприятия цвета (спокойствие даёт низкая насыщенность
при высокой светлоте; сине-зелёный признан самым «приятным» и низковозбуждающим оттенком).

Полный справочник — файл `wellnara-sea-glass-guide.html` (палитра, типографика, отступы,
компоненты, примеры экранов, do/don't, доступность). Он — источник истины по визуалу.

Три принципа, обязательные для каждого экрана:
1. **Спокойствие** — низкая насыщенность, много воздуха, никакого визуального шума.
2. **Ясность** — каждый блок отвечает на один вопрос; второстепенное скрыто.
3. **Доступность** — контраст, заметный фокус, состояния для всего.

---

## 2. Токены — единственный источник значений

Все значения (цвета, радиусы, отступы, тени, шрифты) живут в
`src/main/resources/static/css/sea-glass.css` как CSS-переменные (`:root`).

- В шаблонах и inline-стилях **не хардкодить** hex/px, если для них есть токен —
  использовать `var(--…)`.
- Новый компонент, который может повториться, оформляется классом в `sea-glass.css`,
  а не разовым inline-стилем в шаблоне.
- Разовая раскладка конкретного экрана допустима в `<style>` внутри его шаблона,
  но опирается на токены.

Ключевые токены: `--sea-primary`, `--sea-primary-hover/-dark/-soft/-tint`,
`--sea-accent` (песок) и `--sea-accent-deep/-soft`, поверхности `--bg/--surface/--surface-2`,
текст `--text/--text-muted/--text-faint`, границы `--border/--border-strong`,
смысловые `--success/--warning/--danger` (+ `-bg`), радиусы `--r-sm/-md/-lg/-pill`,
отступы `--s-1…--s-16` (шаг 4/8), тени `--sh-sm/-md/-lg`.

---

## 3. Типографика

- **Inter** — интерфейс и основной текст.
- **Fraunces** (мягкий serif) — только крупные заголовки и «настроенческие» строки
  (вход, hero, пустые состояния). Не использовать для мелкого текста и подписей.
- Веса: 400 (обычный), 500 (заголовки), 600 (акцентный/H3). **Без 700+ и без ALL CAPS**
  в основном тексте.
- Регистр — как в предложении (sentence case) везде: кнопки, заголовки, лейблы.
- Шрифты подключаются с Google Fonts CDN. Задел: при желании позже перейти на self-host
  (первый рендер сейчас требует интернета).

---

## 4. Раскладка и структура страницы

- Контейнер контента — `.page` (потолок ширины ~880px, центрирование, вертикальные отступы).
- Заголовок экрана — `.page-head` + `.page-title` (Fraunces).
- Разделы — `.section-head` (лейбл + опц. `.count-pill`).
- Отступы кратны 4 (основной шаг 8). Воздух между смысловыми блоками — не жалеть.
- Радиусы: 8 — поля/кнопки, 12–16 — карточки/крупные блоки, pill — бейджи.
- Тени сдержанные (`--sh-sm` для карточек); тень обозначает уровень, а не украшает.

---

## 5. Шапка приложения и место Logout

- Единая шапка — фрагмент `templates/fragments/app-header.html`, фрагмент `header(role)`.
  Подключение на любом авторизованном экране:
  `<div th:replace="~{fragments/app-header :: header('Provider')}"></div>`.
- Слева — **логотип**: кружок (`.logo-mark`, placeholder) + вордмарк «Wellnara».
- Справа — **роль** (бейдж) и кнопка **Log out** (`.btn-secondary.btn-sm`, ссылка на
  `/auth/logout`). Шапка sticky.
- **Правила, обязательные к соблюдению:**
  - Logout находится в одном и том же месте (верх-право) на **всех** авторизованных экранах.
  - Роль (и любой контекст пользователя) **никогда** не размещается рядом с логотипом —
    только в правой части шапки.
  - Кружок логотипа — временный placeholder под будущую фигуру/рисунок. Меняется
    в одном месте (фрагменте) и обновляется на всех экранах сразу.

Экран входа (`login.html`) — единственный без общей шапки: он до авторизации и использует
собственную hero-карточку. Бренд там показывается один раз (в hero), заголовок его не дублирует.

## 6. Компоненты (используем эти, не изобретаем заново)

- **Кнопки:** одна `.btn-primary` (главное действие) на экран; остальное — `.btn-secondary`
  / `.btn-ghost`. Песочный акцент — вторичный, **не** для основных действий.
- **Поля:** обёртка `.field` (label + input + опц. `.hint`); видимое кольцо фокуса.
- **Списки записей вместо таблиц:** `.list` + `.list-row` (аватар-инициал `.avatar`,
  имя+email `.who`, бейдж, действие иконкой). Простых `<table>` как визуального
  представления данных быть не должно.
- **Бейджи/статусы:** `.badge-primary/-success/-warning/-danger` — приглушённые, в тон палитре.
- **Уведомления:** `.alert-success/-warning/-danger` вместо «красного/зелёного текста».
- **Иконочные кнопки:** `.btn-icon` (обязателен `aria-label`); деструктив краснеет по hover.
- **Пустые состояния:** `.empty` — короткая дружелюбная строка, не «Nothing here».
- **Метрики** (для дашбордов): карточка «заголовок + число + тренд», один вопрос на карточку.

---

## 7. Копирайт и тон

- Язык интерфейса — **английский**.
- Sentence case; без восклицаний в системных сообщениях.
- **Без дублирования бренда** на одном экране (если вордмарк уже есть — заголовок его не повторяет).
- Заголовки формулируются так, чтобы подходить и первому входу, и повторному
  (не предполагать «возвращение», если экран видят и новички).
- Ошибки: что произошло + что делать, одной фразой, без «Error:» и без сырых исключений.
- Тон — спокойный, тёплый, лаконичный (в духе Sea Glass).

---

## 8. Адаптивность

- Интерфейс выглядит **согласованно на телефоне, планшете и десктопе** «из коробки».
- Обязателен `<meta name="viewport" …>`.
- Контент с потолком ширины и центрированием; на узких экранах — уменьшение отступов
  через media-запросы (ориентир перелома ~420–520px).
- Проверять поведение на малых ширинах (≈320px) до сдачи экрана.

---

## 9. Доступность

- Ровно один смысловой `<h1>` на страницу (структура + скринридеры).
- Контраст текста к фону ≥ 4.5:1 (крупный ≥ 3:1). Базовые пары Sea Glass это проходят.
- Каждый интерактивный элемент имеет видимое состояние фокуса.
- Иконочные кнопки — с `aria-label`; статусы не передаются только цветом (дублировать словом).
- Уважать `prefers-reduced-motion` (уже учтено в `sea-glass.css`).

---

## 10. Технические ограничения и неприкосновенное

- Текущий стек — **серверный рендеринг на Thymeleaf** (до решения вопроса Thymeleaf vs SPA,
  см. раздел 12). Оформление ведётся в существующих шаблонах.
- **Не менять и не удалять Thymeleaf-биндинги** при рестайле: `th:action`/`method` форм,
  `name` полей, `th:if`/`th:each`/`th:text`, имена модельных атрибутов, action удаления/инвайта,
  ссылки на `/auth/logout` и т.п. Оформление меняет разметку и стили, но не контракт с бэкендом.
- Бизнес-логику и контроллеры на этапе UI **не трогаем** (сопутствующие замечания —
  отдельно, как опциональные; исправления бэкенда идут вне UI-задач).
- Файловая раскладка:
  - шаблоны — `src/main/resources/templates/…`,
  - фрагменты — `src/main/resources/templates/fragments/…`,
  - стили — `src/main/resources/static/css/…` (`@{/css/…}` резолвится автоматически).

---

## 11. Процесс работы над экраном

1. Прочитать реальный шаблон и его биндинги (не по памяти).
2. Перекомпоновать по разделам 4–7; переиспользовать компоненты, а не плодить новые.
3. Сохранить все биндинги; проверить их наличие после правок.
4. Показать визуальный превью и указать точное место файлов в структуре репозитория.
5. Прямо сообщать, что не удалось проверить в окружении (например, реальную сборку/рендер
   Thymeleaf) — без вида, что проверка пройдена.

## 12. Статус и открытые решения

**Сделано:**
- Направление Sea Glass выбрано и зафиксировано; гайд `wellnara-sea-glass-guide.html`.
- `static/css/sea-glass.css` — токены + компоненты (кнопки, поля, алерты, бейджи,
  шапка, список записей, иконочная кнопка, пустое состояние). Токен `--danger-dark`
  (#8f3729) — тёмный текст на danger-фоне (используется в `.alert-danger` и chip
  «Unavailable»).
- `templates/fragments/` — переиспользуемая шапка `app-header :: header(role)`,
  навигация кабинетов `client-nav`, `provider-nav`.
- **Все экраны переоформлены** (Sea Glass, единая шапка/оболочка, адаптивность, токены):
  - pre-auth: `login`, `client-register`, `provider-register` (hero-карточка, без общей шапки), `error`;
  - провайдер: `provider-home`, `provider-clients`, `provider-offerings`,
    `provider-appointments`, `provider-availability`, `provider-profile`,
    `provider-client-wallet`, `offering-edit`;
  - клиент: `client-home`, `client-offerings`, `client-offering`,
    `client-appointments`, `client-profile`;
  - `admin`.

**Осталось переоформить:** — отдельных экранов не осталось. Ранний единый кабинет
`provider.html`/`client.html` разбит на пофункциональные страницы (перечислены выше);
списка из прежней версии этого раздела больше не существует. Дальнейшие правки UI —
точечные (в рамках задач по функционалу), с соблюдением разделов 1–11.

**Открытые решения (не блокируют UI-этап, но держим в уме):**
- **Thymeleaf vs SPA (React).** Пока остаёмся на Thymeleaf; при переходе на SPA токены
  Sea Glass переносятся напрямую. Решение принимает Nik.
- **Заголовок экрана входа.** Идею замены «Welcome» пока не нашли — временно оставлено «Welcome».
- **Логотип.** Кружок — placeholder под будущую фигуру/рисунок.
